## 7. THE STAGE-2 PROOF — two simultaneously eligible candidates, route named

### 7.1 PK's requirement, restated exactly

**A size-one candidate set is not acceptable proof.** The proof must use **at least two simultaneously
eligible candidates**:

- **Candidate A:** `is_primary = true`, `is_default_host = false`
- **Candidate B:** `is_primary = false`, `is_default_host = true`
- **Candidate B must win.**
- **And the fallback with no default host present must also be proven.**

**Why this test is exactly right — it does double duty.** Under the **PK-ruled** order B wins (rank 2
beats rank 3). Under the **shadow** order **A** wins (`is_primary` first). So the A/B test does not
merely prove "designation is consulted" — **it discriminates which of the two orders actually
shipped.** A resolver that quietly kept the shadow precedence fails this test loudly.

### 7.2 The trap this replaces

Every production candidate set today has size 1 (two clients with one active designated avatar each;
the other two clients have **no rows at all**). On a size-1 set, *"reads the designation"* and *"still
reads storage order"* return the **identical row**. **Parity is the baseline and is NOT evidence.** A
proof that cannot fail is not a proof. This is the `declared-control-not-consulted` failure mode, and
this lane is the one most exposed to it.

It would be the natural replay harness, but: it **writes** a row to `r.avatar_resolution_shadow`, it
